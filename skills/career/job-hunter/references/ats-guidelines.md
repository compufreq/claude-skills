# ATS Formatting Guidelines

Applicant Tracking Systems (ATS) are automated tools that parse, store, and rank résumés before a human ever sees them. A beautifully designed CV that an ATS can't parse is worse than a plain one it can. These guidelines ensure documents pass through ATS parsing cleanly.

## Document Structure

### File Format
- Primary output: `.docx` (most widely supported by ATS platforms)
- Secondary output: `.pdf` (for the user's own records and manual submissions)
- The `.docx` is the application-ready version. The `.pdf` is a visual reference copy.

### Layout Rules
- **Single column layout only.** Multi-column layouts, text boxes, and tables-as-layout break ATS parsing. Use standard paragraphs and headings.
- **No headers or footers for critical info.** Many ATS systems skip header/footer content. Put the candidate's name and contact info in the document body, not in a header.
- **No text boxes or floating elements.** These are invisible to most parsers.
- **No images, icons, logos, or graphics.** Skill bars, progress circles, star ratings, headshot photos — all of these are invisible to ATS and waste space.
- **Standard margins.** Use 1-inch (2.54 cm) margins on all sides. 0.75-inch is acceptable if space is tight.

### Fonts
- Use standard, widely available fonts: Calibri, Arial, Helvetica, Times New Roman, Georgia, Cambria, or Garamond.
- Font size: 10–12pt for body text, 14–16pt for the name, 12–14pt for section headings.
- Avoid decorative or unusual fonts — ATS may not recognize them.

### Section Headings
Use conventional, recognizable section headings. ATS systems look for standard labels:

- **Contact Information** (or just the name at the top)
- **Professional Summary** or **Summary** (not "About Me" or "Profile")
- **Work Experience** or **Experience** (not "Career Journey" or "My Path")
- **Education**
- **Skills** (not "Toolbox" or "Arsenal")
- **Certifications** (if applicable)
- **Projects** (if applicable)
- **Languages** (if applicable)

Use Word's built-in heading styles (Heading 1, Heading 2) for section headings — this gives the document semantic structure that ATS can parse.

### Formatting Do's and Don'ts

**Do:**
- Use bullet points (simple round bullets) for listing achievements and responsibilities
- Use bold for job titles and company names
- Use consistent date formatting (e.g., "Jan 2020 – Present" or "2020–2024")
- Use standard characters — no special symbols, emojis, or unicode decorations
- Keep it to 1–2 pages (1 page for <5 years experience, 2 pages for 5+ years)

**Don't:**
- Use tables to structure the layout (single-row tables for alignment are risky)
- Use colored text (stick to black)
- Use background colors or shading
- Use abbreviations without the full term (write "Search Engine Optimization (SEO)" first, then "SEO" after)
- Use creative section dividers (decorative lines, shapes, etc.)

## Content Optimization for ATS

### Keywords
- Mirror the exact language from job descriptions. If the listing says "project management," use "project management" — not just "managed projects."
- Include both spelled-out terms and common acronyms: "Cascading Style Sheets (CSS)"
- Place the most important keywords in the Skills section and in the top third of the document.

### Work Experience Format
For each role, use this structure:
```
**Job Title**
Company Name | Location | Start Date – End Date

- Achievement or responsibility using action verb + measurable result
- Another achievement with specific numbers where possible
```

Action verbs that ATS and recruiters respond well to: Led, Developed, Implemented, Designed, Managed, Optimized, Increased, Reduced, Delivered, Automated, Built, Launched, Scaled, Mentored, Negotiated.

### Skills Section
- List skills as a simple comma-separated list or a clean bullet list
- Group by category if there are many (e.g., "Programming Languages:", "Cloud Platforms:", "Tools:")
- Include both hard skills (technologies, tools, methodologies) and soft skills (leadership, communication)
- Match skill names to industry-standard terminology

## Cover Letter ATS Notes

Cover letters are parsed less aggressively than CVs, but still follow these rules:
- `.docx` format, single column, no graphics
- Include the candidate's name, contact info, date, and the recipient's info at the top
- Use a standard business letter format
- Keep to one page
- Include relevant keywords from the job listing naturally in the body text
- Use the same font family as the CV for visual consistency
