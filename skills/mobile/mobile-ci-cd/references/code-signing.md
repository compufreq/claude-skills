## 1. iOS Code Signing Overview

### Components

| Component | What It Is | Where |
|-----------|-----------|-------|
| **Certificate** | Proves your identity as a developer | Apple Developer Portal + Keychain |
| **Private Key** | Paired with certificate, signs the binary | Keychain (never share directly) |
| **App ID** | Unique identifier for your app | Apple Developer Portal |
| **Provisioning Profile** | Links certificate + App ID + devices + entitlements | Apple Developer Portal |
| **Entitlements** | Capabilities (push, HealthKit, etc.) | Xcode project |

### Profile Types

| Type | Use | Devices | Distribution |
|------|-----|---------|-------------|
| **Development** | Debugging on device | Registered (max 100) | Direct install |
| **Ad Hoc** | Internal testing | Registered (max 100) | Direct / MDM |
| **App Store** | TestFlight + App Store | Any (via Apple) | App Store / TF |
| **Enterprise** | In-house distribution | Any (company) | MDM / direct |

## 2. Fastlane match (Recommended)

`match` stores certificates and profiles in a Git repo (or cloud storage), encrypted.
The entire team (and CI) shares the same signing identity.

### Initial Setup
```bash
# Initialize match
fastlane match init
# Choose storage: git, s3, or google_cloud
# Enter git URL for certificate repo

# Generate certificates (run ONCE, by team lead)
fastlane match development
fastlane match appstore
fastlane match adhoc  # if needed
```

### Matchfile
```ruby
# fastlane/Matchfile
git_url("https://github.com/myorg/certificates.git")
storage_mode("git")
type("appstore")
app_identifier(["com.example.myapp", "com.example.myapp.widgets"])
username("developer@example.com")
team_id("ABCDE12345")
```

### Usage in Fastfile
```ruby
# Development
lane :certs_dev do
  match(type: "development", readonly: is_ci)
end

# App Store (release)
lane :certs_release do
  match(type: "appstore", readonly: is_ci)
end

# Ad Hoc (Firebase distribution)
lane :certs_adhoc do
  match(type: "adhoc", readonly: is_ci)
end
```

### CI Setup with match

```ruby
# In Fastfile, before build lanes:
lane :setup_ci_signing do
  create_keychain(
    name: "ci_keychain",
    password: ENV["KEYCHAIN_PASSWORD"],
    default_keychain: true,
    unlock: true,
    timeout: 3600,
    lock_when_sleeps: false,
  )

  match(
    type: "appstore",
    readonly: true,
    keychain_name: "ci_keychain",
    keychain_password: ENV["KEYCHAIN_PASSWORD"],
    git_basic_authorization: Base64.strict_encode64(
      "#{ENV['MATCH_GIT_USERNAME']}:#{ENV['MATCH_GIT_TOKEN']}"
    ),
  )
end
```

### Required CI Secrets for match

| Secret | Description |
|--------|------------|
| `MATCH_PASSWORD` | Encryption password for the certificates repo |
| `MATCH_GIT_URL` | URL of the certificates Git repo |
| `MATCH_GIT_BASIC_AUTHORIZATION` | Base64-encoded `username:token` for Git auth |
| `KEYCHAIN_PASSWORD` | Password for the temporary CI keychain |

### Using App Store Connect API Key (No Apple ID Needed)

```ruby
# Preferred for CI — no 2FA issues
app_store_connect_api_key(
  key_id: ENV["ASC_KEY_ID"],           # e.g., "ABC123DEF4"
  issuer_id: ENV["ASC_ISSUER_ID"],     # e.g., "12345678-..."
  key_content: ENV["ASC_KEY_CONTENT"], # Base64-encoded .p8 content
  is_key_content_base64: true,
  in_house: false,
)
```

Generate the API key in App Store Connect → Users and Access → Keys.

## 3. Manual iOS Signing (Without match)

### Xcode Automatic Signing
- Works for development — Xcode manages everything
- Not recommended for CI — requires Apple ID with 2FA

### Manual Process
1. Create certificate in Apple Developer Portal
2. Export .p12 from Keychain (certificate + private key)
3. Create provisioning profile in Developer Portal
4. Import .p12 and profile on CI machine
5. Set in Xcode: manual signing, select profile

### CI with Manual Signing
```ruby
# Import certificate
import_certificate(
  certificate_path: "path/to/cert.p12",
  certificate_password: ENV["CERT_PASSWORD"],
  keychain_name: "ci_keychain",
  keychain_password: ENV["KEYCHAIN_PASSWORD"],
)

# Install provisioning profile
install_provisioning_profile(path: "path/to/profile.mobileprovision")

# Build with specific profile
gym(
  export_options: {
    signingStyle: "manual",
    provisioningProfiles: {
      "com.example.myapp" => "MyApp AppStore Profile",
    },
  },
)
```

## 4. Android Signing

### Keystore Types

| Type | Use | Generated By |
|------|-----|-------------|
| **Debug keystore** | Development builds | Android SDK (auto) |
| **Upload keystore** | Signing uploads to Play Store | Developer (keytool) |
| **App signing key** | Final APK signing | Google (Play App Signing) |

### Play App Signing (Recommended)
- Google manages the app signing key (most secure)
- You sign with an upload key (can be reset if compromised)
- Enable in Play Console → App Integrity → App Signing

### Keystore Generation
```bash
keytool -genkey -v \
  -keystore upload.keystore \
  -alias upload \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000
```

### Signing in Gradle
```kotlin
android {
    signingConfigs {
        create("release") {
            storeFile = file(System.getenv("KEYSTORE_PATH") ?: "upload.keystore")
            storePassword = System.getenv("KEYSTORE_PASSWORD") ?: ""
            keyAlias = System.getenv("KEY_ALIAS") ?: ""
            keyPassword = System.getenv("KEY_PASSWORD") ?: ""
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}
```

### Required CI Secrets for Android

| Secret | Description |
|--------|------------|
| `KEYSTORE_BASE64` | Base64-encoded keystore file |
| `KEYSTORE_PASSWORD` | Keystore password |
| `KEY_ALIAS` | Key alias within keystore |
| `KEY_PASSWORD` | Key password |
| `PLAY_STORE_JSON_KEY` | Base64-encoded Play Store service account JSON |

### CI Keystore Setup
```bash
# Encode (once, locally)
base64 -i upload.keystore | tr -d '\n' > keystore.b64
# Store content of keystore.b64 as KEYSTORE_BASE64 secret

# Decode (in CI pipeline)
echo "$KEYSTORE_BASE64" | base64 --decode > upload.keystore
```

## 5. CI Signing Setup Summary

### iOS (GitHub Actions)
```yaml
- name: Setup signing
  env:
    MATCH_PASSWORD: ${{ secrets.MATCH_PASSWORD }}
    MATCH_GIT_URL: ${{ secrets.MATCH_GIT_URL }}
    MATCH_GIT_BASIC_AUTHORIZATION: ${{ secrets.MATCH_GIT_AUTH }}
    ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
    ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
    ASC_KEY_CONTENT: ${{ secrets.ASC_KEY_CONTENT }}
    KEYCHAIN_PASSWORD: ${{ secrets.KEYCHAIN_PASSWORD }}
  run: bundle exec fastlane setup_ci_signing
```

### Android (GitHub Actions)
```yaml
- name: Decode keystore
  run: echo "${{ secrets.KEYSTORE_BASE64 }}" | base64 --decode > upload.keystore

- name: Build signed AAB
  env:
    KEYSTORE_PATH: ${{ github.workspace }}/upload.keystore
    KEYSTORE_PASSWORD: ${{ secrets.KEYSTORE_PASSWORD }}
    KEY_ALIAS: ${{ secrets.KEY_ALIAS }}
    KEY_PASSWORD: ${{ secrets.KEY_PASSWORD }}
  run: ./gradlew bundleRelease
```

## 6. Troubleshooting

### iOS Signing Issues

| Error | Cause | Fix |
|-------|-------|-----|
| "No profiles match" | Bundle ID mismatch or missing profile | Run `match` or check App ID in portal |
| "Certificate not found" | Certificate not in keychain | Import .p12 or run `match` |
| "Profile doesn't include signing certificate" | Profile was made with a different cert | Regenerate profile: `match nuke` + `match` |
| "Code signing is required" | Xcode can't find signing identity | Check team selection in Xcode signing settings |
| "Provisioning profile expired" | Profile > 1 year old | Regenerate: `match --force` |
| "This certificate has been revoked" | Certificate manually revoked | Run `match nuke distribution` + `match appstore` |

### Android Signing Issues

| Error | Cause | Fix |
|-------|-------|-----|
| "keystore was tampered with" | Wrong password or corrupted file | Check `KEYSTORE_PASSWORD`, re-encode base64 |
| "Keystore file not found" | Path incorrect | Verify `KEYSTORE_PATH` points to decoded file |
| "Key alias not found" | Wrong alias name | Check `KEY_ALIAS` matches keystore contents |
| "SHA-256 mismatch" | Signed with wrong key | Use the same keystore that was uploaded to Play Console |

### General CI Issues

| Issue | Fix |
|-------|-----|
| Flaky tests failing CI | Add retry logic, mark flaky tests, investigate root cause |
| Build timeout | Increase timeout, optimize build (caching, incremental) |
| Secret not available | Check secret name, scope (repo vs org), environment |
| Stale cache | Clear CI cache, verify cache key includes dependency lock files |
